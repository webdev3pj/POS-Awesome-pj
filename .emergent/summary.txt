<analysis>**original_problem_statement:** 
My business runs on ERPNext, hosted on Frappe Cloud, and we heavily use POS Awesome. We need a token-based system for our hardware store. The store has multiple counters for punching orders but only one for cashiering.

**PRODUCT REQUIREMENTS:**
1.  **Sales Associate Workflow:**
    *   The associate takes an order, looks up or creates a customer, and adds items to the cart.
    *   Instead of collecting payment, they generate a receipt with a QR code (token).
    *   The associate should not be able to process payments, returns, or create final invoices. They should be able to save/hold draft orders.
2.  **Cashier Workflow:**
    *   The customer brings the QR receipt to the cashier.
    *   The cashier scans the QR code to retrieve the complete order details.
    *   The cashier can modify the order if the customer changes their mind.
    *   The cashier collects payment and issues the final Sales Invoice.
3.  **Roles & Permissions:**
    *   Create two new roles:  and , with corresponding Role Profiles.
    *   These users should only have access to POS Awesome.
    *   The UI must be tailored to each role, showing only the buttons they are authorized to use.
4.  **Technical & UI:**
    *   The system should be a custom app/extension for POS Awesome, built on the  branch of the provided repository.
    *   The token should store the Sales Associate's data for commission purposes.
    *   The cashier should have a view of all pending/outstanding tokens.
    *   The UI for the Sales Associate should prominently display a Generate Token button and show who is logged in.
    *   The UI for the Cashier should be streamlined for scanning tokens and processing payments, and it should display which Sales Associate created the loaded order.
5.  **Commission:**
    *   The system must link the Sales Associate to the final transaction to enable commission calculation (e.g., 0.5% of the net amount).
